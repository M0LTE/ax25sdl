# ADR-0003 — Rust backend: typed closed sets + `no_std` + publishable crate

- **Status:** Accepted
- **Date:** 2026-06-04
- **Deciders:** Tom Fanning M0LTE; Claude (Opus 4.8) implementing

## Context

[ADR-0002](0002-typed-guard-and-event-closed-sets.md) gave action verbs, guard atoms, and events a typed closed-set treatment — `Ax25ActionVerb` / `Ax25Guard` / `Ax25Event` plus a `GuardTerm(atom, negate)` — but only in the **C# and TS** backends, mirroring how SP-010 shipped `Ax25ActionVerb` for C#/TS only. ADR-0002's "Alternatives considered #4" recorded that emitting the closed set in the other backends was "a separate decision if/when those runtimes want compile-checked binding." This ADR is that decision for **Rust**.

The driver is a concrete downstream consumer: an embedded AX.25 node on a Raspberry Pi Pico W (`thumbv6m-none-eabi`, Cortex-M0+), which needs to walk the generated SDL tables from a `no_std` crate and `match` exhaustively on verbs/events. Two gaps blocked that:

1. The Rust backend was still **stringly-typed** — `RustEmitter.cs` wrote `verb` / `guard` / `on` / loop `predicate` as raw `&'static str`. An exhaustive `match` was impossible; a typo'd verb was a runtime `expect`/lookup failure, not a compile error.
2. The generated crate was **not `no_std`** (no `#![no_std]`) and **not publishable** (`publish = false`, nominal metadata). An external embedded crate could not depend on it.

## Decision

### 1. Port the ADR-0002 typed closed sets to the Rust emitter

The Rust backend now emits, exactly as C#/TS do:

- `ax25_action_verb.g.rs` → `pub enum Ax25ActionVerb` — the closed set of canonical action verbs.
- `ax25_guard.g.rs` → `pub enum Ax25Guard` — the closed set of canonical guard atoms, **gathered from the resolved IR** (so it includes Resolver-synthesised atoms that never appear as a raw `predicate:`, e.g. `vs_eq_nr` from the ax25sdl#53 stale-read substitution).
- `ax25_event.g.rs` → `pub enum Ax25Event` — one variant per `spec-sdl/events.yaml` entry.

Each enum derives `Debug, PartialEq, Eq, Clone, Copy, Hash`, orders variants by canonical string for a stable diff, and carries the canonical text as a `///` doc comment. The generated tables reference the enums instead of strings:

- `ActionStep.verb` : `Ax25ActionVerb`
- `TransitionSpec.on` : `Ax25Event`
- `TransitionSpec.guard` / `SubroutinePath.guard` : `&'static [GuardTerm]` — a conjunction; empty slice `&[]` = unguarded.
- `LoopRange.predicate` : `GuardTerm` (carries the loop's `not`).

`GuardTerm { atom: Ax25Guard, negate: bool }` is hand-written in `spec/rust/src/types.rs`, the Rust counterpart of the C# `GuardTerm` record / TS `GuardTerm` interface.

**Enum-member folding is byte-identical to the C# emitter's**, so the closed-set member names are nominally the same across the three typed backends (`SendDisc`, `PeerReceiverBusy`, `DLDISCONNECTRequest`, `DMFEq1`). Rust accepts acronym-run PascalCase variant names without a `non_camel_case_types` warning (verified). The composed guard string is parsed back into terms by the existing language-neutral `GuardExpression` parser in `Packet.Sdl.IR` — the same parser C#/TS use — so a future top-level `or` fails codegen loudly for Rust too rather than being silently mis-encoded.

The fix is in the **emitter**, not the generated files; the `.g.rs` artefacts are regenerated. The orchestrator's typed-set emission block was un-gated from `EmitCsharp || EmitTs` to also fire for `EmitRust`, so a `--rust`-only run emits the enums (the Rust CI drift job runs `--rust` alone).

### 2. `no_std`-capable crate with a default-on `std` feature

`src/lib.rs` (generated by `EmitLib`) carries `#![cfg_attr(not(feature = "std"), no_std)]`. `Cargo.toml` declares:

```toml
[features]
default = ["std"]
std = []
```

Host `cargo test` / `cargo build` use the default (std on) so the test harness links `std`; an embedded consumer depends with `default-features = false`, which flips the crate to `#![no_std]`. The `std` feature gates **no API surface** — the entire data/type core is already `no_std`-clean: every type is `Copy`, holds only `&'static` borrows + scalars + the closed-set enums, and touches no allocator. The feature exists solely so the test harness can link `std`.

### 3. Publishable crate metadata

`publish = false` is removed and the manifest gets real crates.io metadata (description, keywords, categories incl. `no-std`/`embedded`, `rust-version`, `homepage`/`documentation`/`readme`, `include`). A crate-local `README.md` and `LICENSE` are added. `cargo package` build-verifies the packaged crate.

This ADR makes the crate **publishable**; it does **not** publish it. The actual version bump + `cargo publish` + the downstream cascade are driven by Tom (see Consequences).

## Alternatives considered

1. **Keep Rust string-typed; only flip `no_std`.** Rejected — the embedded consumer's whole motivation is compile-checked exhaustive dispatch; ADR-0002's argument applies identically to Rust.
2. **Diverge Rust enum-member names to "more idiomatic" snake-to-Pascal (`DlDisconnectRequest`).** Rejected — reusing the C# fold keeps the closed sets nominally identical across backends (one mental model, trivial cross-backend diffing) and Rust accepts the acronym-run form cleanly. If a future Rust consumer wants the camel-cased acronym style, that's a separable follow-up.
3. **A `std`-gated convenience API surface (e.g. `Display`, `error::Error`).** Not done — out of scope; the core is data + closed enums. The feature is a pure link-time switch today, which keeps the `no_std` guarantee trivial to reason about.
4. **Extend the typed sets to the remaining string backends (Go / C / Python / JSON) in the same change.** Not done — same staging discipline ADR-0002 used. Each is its own decision when a consumer needs it.

## Consequences

### Positive

- A Rust consumer (embedded or hosted) can `match` exhaustively on `Ax25ActionVerb` / `Ax25Event` / `Ax25Guard`; a renamed/typo'd/removed member is a compile error. Proven with a `#![no_std]` consumer crate doing a wildcard-free `match` over the full event set.
- The crate builds `--no-default-features` (`no_std`) and `cargo package`-verifies, so an external embedded crate can depend on it.
- Zero churn to the C#/Go/TS/C/Python/JSON generated outputs — the change is surgically Rust-only (verified: a full regen touches only `spec/rust/`).

### Negative

- **Breaking change** to the generated Rust crate's public types (`ActionStep.verb`, `TransitionSpec.on`/`guard`, `SubroutinePath.guard`, `LoopRange.predicate`) and three new generated files — the same shape of break ADR-0002 made for C#/TS. No in-tree Rust consumer existed, so nothing in this repo breaks; an external consumer pins a version.
- One more hand-written type to keep in sync across the typed backends (`GuardTerm` now in C#, TS, **and** Rust).

### Publish / version / cascade (for Tom)

- The crate version stays at the nominal `0.7.0` in this PR. Because the public types change shape, the **first published version must signal the break** — bump to at least `0.8.0` (pre-1.0 SemVer treats a minor bump as the breaking signal), or pick the version deliberately at publish time.
- Publishing is `cargo publish` from `spec/rust/` against a crates.io token. `ax25sdl` is an **available** crate name on crates.io as of writing — confirm at publish time.
- This repo feeds a downstream cascade (packet.net via NuGet, ax25-ts via npm). The Rust crate is a **new** externally-consumable artefact with **no current downstream consumer**, so publishing it does not cascade today; the Pico-W node crate is the intended first consumer. The other backends' publish workflow (`publish.yml`, NuGet+npm on `v*` tag) is unaffected — Rust publish is a separate manual `cargo publish` for now.
